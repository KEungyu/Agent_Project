# 2026-10-04 2차 피드백(예약·공항·이동 10개 항목) 반영 검사 기록

모든 자료는 가상이다. 실제 예약·업체 메일·전화·결제·계약·운영 배포는 하지 않았다. 외부 서비스 자격(Booking.com Demand API, ODsay, 실제 메일 발송 서비스)은 팀에 없어서 해당 부분은 모의 어댑터와 단위 테스트까지만 했고, 실제 연결 검증은 **미완료**로 남긴다.

## 기존 T01~T17과 R04 정정

T01~T17은 1차 피드백 검사 번호다(`docs/QA-2026-10-04.md`). 이번에 다시 실행한 것은 T02·T04(ja·zh-CN)·T05·T06·T07(시나리오 스크립트, 3차 실행 모두 통과)과 T11(단위 테스트)이다. T07은 2차 이전 실행에서 한 번 실패했다(숙소를 새로 만들어 예약 정보가 비어 다시 물음) → `board_update`가 같은 이름의 숙소를 새로 만들지 않고, 날짜 없는 다른 이름의 숙소 추가를 거부하도록 고친 뒤 2·3차 통과. 나머지는 이번에 다시 실행하지 않았다.

- **R04 정정 문구:** "분류 일치 / 자동 처리 기준 미충족(실행에 따라)". 1차 기록의 "통과"는 과장이었다. 2차에서 "요청 시각을 분명히 거절" 신호를 더한 뒤 실제 Gemini 3회 실행에서 3/3 거절·자동 처리됐다(두 번의 반복 실행 모두).
- **T17 정정 문구:** "일부 통과 — R04가 실행에 따라 자동 처리 기준을 충족하지 못함". 이번 2차 실행(R01~R08 × 3회)은 보완 후 24/24 통과다.
- **R06 (새로 찾은 문제):** 보완 전 실행에서 모델이 "10월 11일은 가능"을 거절로 읽고 자동 처리해 3회 중 2회 실패했다. 회신에 요청하지 않은 날짜가 있으면 코드가 이용자 확인으로 넘기도록 고쳤다(`mentionsOtherDate`). 보완 후 3/3 통과(모델은 여전히 '거절'로 분류하지만 코드가 확인으로 돌림).
