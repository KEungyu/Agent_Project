# 2026-10-04 피드백 반영 검사 기록

## 실행 환경

| 항목 | 값 |
|---|---|
| 코드 | 로컬 작업 트리 (이 기록 시점 커밋 전) |

## 남은 결정과 다음 작업

1. 회신 R04 같은 거절이 가끔 확인으로 넘어간다. 안전한 쪽이라 그대로 두었다. 줄이려면 날짜 불일치 신호를 수락·조건부에만 적용하는 방안이 있지만, 그러면 모델이 R06을 "거절"로 잘못 분류할 때 자동 처리될 수 있다.
2. 화면 클릭 기반 검사(빠른 중복 클릭, 이어서 보기, 번역·모의 처리 실패 주입)와 음성 확인은 미실행.
3. 베트남어·태국어·인도네시아어·스페인어·번체 중국어의 동적 초안·번역은 원어민 또는 실제 사용자 검토가 필요하다.
4. 대화 기록은 서버 메모리에만 있어 재시작하면 사라진다. 저장소에 남기려면 데이터 모델 변경이라 별도 승인이 필요하다.

## 설명서 수정이 필요한 부분

- 전화 칸: "도착 6시간 이내" → "도착까지 6시간이 안 남았을 때"(코드는 6시간 미만).
- 승인 버튼 이름: "확인하고 보내기" → "확인하고 보내기(시연)", 승인 전 확인 사실·받는 곳 요약, 메일 앱 경로 안내 추가.
- 택시비 계산기: "적정 요금" → "예상 요금", 서울 출발·도착만 계산, 계산기의 공항 버튼은 인천·김포만.
- 채팅: 도구 이름 표시 삭제, 초안을 만들면 확정한 날짜·시각이 답에 함께 나옴, "오늘 새벽 N시"처럼 이미 지난 시각은 날짜를 한 번 확인.
- 회신: 확신할 수 없는 회신은 "마중이의 추측(확정 아님)"으로 보이고 이용자가 직접 분류를 고름.
- 오프닝: 기존 여행이 있으면 "입국하기"가 새 여행을 시작한다는 경고가 보임.
