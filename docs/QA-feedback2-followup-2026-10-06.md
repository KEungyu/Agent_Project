# 2차 피드백 후속 보완·검증 보고 — 2026-10-06

> **최신 상태(10/07):** 실제 ODsay·새 화면 대조와 회신 평가 28건의 재검증을 마쳤다. 최종 결과는 [3차 피드백 결과 문서](QA-feedback3-2026-10-07.md)를 기준으로 본다. 아래 인증 실패·한도 초과·미완료 기록은 당시 이력으로 보존한다.

기준은 `main`의 `eceff490194f8f3eb5fee78cc0f0d05890dda8a9`와 이어받은 커밋 전 변경이다. 기존 작업을 보존하고 미완료 항목을 보완했다. 각 실행 로그에는 전체 SHA·변경 해시·실행 ID·옵션·시작/종료 시각을 남겼다. **SHA만으로 현재 작업 내용을 재현할 수는 없다.** 이번에는 커밋·푸시·배포·실제 발송·예약·전화·결제·의존성 변경·저장 스키마 변경을 하지 않았다.

이 문서는 현재 확인 결과다. [이전 QA 보고](QA-feedback2-2026-10-04.md)의 오전 성공, 저녁 실패, 초기 보류 판단은 당시 이력으로 보존한다. 특히 “공항 출발 입력 보류”, “Catchtable 기록에는 스키마 변경 필요”, “모든 공항 시설 일반구역 확인”은 아래 결과로 갱신한다.

## 공식 자료·외부 장애와 다음 행동

- **ODsay:** 로컬 `.env` 키를 출력하지 않고 `searchSubwaySchedule`(201/상행), `subwayPathSchedule`(201→222, MODE=1, DAY=1, TIME=2100)을 각 1회 호출했다. 둘 다 HTTP 200 안의 제공사 코드 `500`, `ApiKeyAuthFailed`, 결과 없음이었다. 실제 키·IP·endpoint 권한 중 어느 것이 원인인지는 이 응답만으로 단정하지 않는다. 담당자는 서버 플랫폼 키, 현재 나가는 IP 등록, 계약 endpoint 권한·한도를 콘솔에서 대조해야 한다. 배포 설정·로그는 접근하거나 변경하지 않았다. 배포 성공 근거 없음.
- [ODsay 공식 문서](https://lab.odsay.com/guide/releaseReference?platform=web)에 시각 지정 API와 첫차·막차 대체 notificationCode가 존재한다. 해당 API는 미연결이다. 현 로컬 키에서 성공한 실제 자료가 생기면 응답 형식·DAY/자정 규칙·대체 결과부터 대조해야 한다. 이번에는 연결도·공식 확인 링크를 대안으로 둔다.
- **Booking:** [공식 전제조건](https://developers.booking.com/demand/docs/getting-started/prerequisites)의 제휴·계약·Partner Centre·API 토큰·Affiliate ID를 확보한 상태가 아니다. 계정 신청·유료 전환 없이 홈 연결을 유지한다. 자격 확보 후에도 목적지 탐색·응답 버전·URL·가격 필드 검증이 필요하다.
- **시설:** [ICN 공식 목록](https://www.airport.kr/ap_en/1536/subview.do), [GMP 공식 목록](https://www.airport.co.kr/gimpo/cms/frCon/index.do?CONTENTS_NO=2&MENU_ID=2390)을 재확인했다. ICN T1 로밍·와이파이·환전·ATM의 기재 위치/시간은 대조했으나 KB 환전소의 이미지 설명과 위치 본문에서 접근 구역이 명확하지 않아 `unconfirmed`로 바꿨다. 김포는 운영시간·접근 구역 미확인을 유지한다. 모든 시설이 일반구역·24시간이라고 주장하지 않는다.
- **Gemini:** 회신 평가 503 이후 나머지를 미실행으로 남겼다. 서비스가 안정된 뒤 `npm run eval:replies`로 전체를 재검증한다. `REVIEW_ONLY=1 npm run eval:replies`는 R01~08만 실행하며 기본 20건 재검증을 대신하지 않는다.
- **저장 구조:** 조건 확인은 기존 상태 이력 메모, 외부 결과는 기존 이벤트 상세, 공항 출발 입력은 화면 상태를 사용했다. 이번 범위에 필요한 스키마 결정은 없다. 외부 결과는 공급자가 검증한 예약 정보로 승격되지 않는다.

### 변경 이유·파일

사용자가 집 와이파이의 공인 IP를 기존 ODsay 앱에 추가한 뒤 `searchSubwaySchedule`과 `subwayPathSchedule` 모두 HTTP 200·result 수신·인증 오류 없음이 확인됐다. 이에 보류했던 시각 지정 경로를 연결했다. 초기 확인은 result와 필드 존재까지이며, 새 파서·화면에서 정상 경로를 검증한 것으로 확대하지 않는다.

- `lib/transit/scheduled.ts`, `schedule-time.ts`: 한국 시각 입력의 날짜 유효성·요일 확인, 공식 역 검색의 이름/좌표 일치로 ID 결정, `MODE=1`·`DAY`·`TIME` 조회. 실제 ID를 표지판 역 번호로 추정하지 않는다.
- `lib/transit/odsay.ts`: 기존 인증·한도·캐시 처리 함수를 시각 지정 조회에서도 재사용하도록 공개했다.
- `app/actions.ts`, `app/components/TransitGuide.tsx`: 공항 출발 시각 확인 후 시각 지정 서버 액션 호출. 시각·공휴일·출도착역 변경 시 확인과 이전 결과 초기화. 일반 경로 결과를 선택 시각 결과로 재사용하지 않는다.
- `lib/i18n/messages.ts`: 시간표 기준·공항 안 도보와 호텔 이동 제외·공휴일·첫차/막차 대체·미상 결과 안내를 9개 언어로 추가했다.
- `lib/transit/scheduled.test.ts`, `scripts/qa/browser-checks.mts`: F2-35~41 및 F2-B8 추가.
