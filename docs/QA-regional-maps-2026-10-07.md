# [R-1 사용자 추가 요청] 부산·대구 자체 연결도와 운영 ODsay 확인

검사일: 2026-10-07 KST. 기준 main: `c465891`. 이 문서는 게시 전 검증 기록이며, PR·배포·운영 지도 확인은 데스크탑 최종 보고서에 덧붙인다.

## 운영 ODsay: 직접 확인한 결과

- Chrome에서 실제 운영 사이트 `https://majungi.onrender.com/` 접근에 성공했다. 이전의 브라우저 접근 제한은 이번 검사에 적용되지 않았다.
- 김은규 계정의 기존 ODsay 앱에서 URI `majungi.onrender.com`, 일일 사용량 **30건/30건**을 확인했다(화면 기준 11:45). 키 값은 기록하지 않았다. 이 사용량은 이번 경로 선택 전에 이미 표시돼 있었다.
- 운영 화면에서 서울역→명동 경로를 선택하자 `Times & fares`에 **일일 한도 초과 (429)**와 공식 안내 링크가 표시됐다. 경로 선택 1회를 실행했으며, 앱 내부 요청 수와 계정 사용량 증가분은 따로 계측하지 않았다.
- 이 결과는 브라우저에서 오류 응답을 읽고 한도 초과를 안내하는 동작의 실제 증거다. 성공 요금 응답이 아니므로 **유효한 인증·정상 경로 요금 성공은 아직 미확인**이다. 제공자가 인증 검사보다 먼저 한도를 검사할 가능성도 배제할 수 없다.
- 추가 ODsay 호출은 중단했다. 키 교체·다른 계정 사용·유료 전환은 하지 않았다. 한도 재설정 후 동일 경로의 숫자 요금·소요시간을 실제 응답과 함께 확인해야 남은 항목을 닫을 수 있다. 임의 예상 요금이나 모의 값을 운영 성공으로 대체하지 않는다.

## 판단과 구현 순서

1. 최신 원격을 가져와 기존 팀 작업과 겹침을 확인했다. 기준 main에는 부산·대구 데이터가 없었다. 김은규 님이 작성했다고 추정하지 않고 기존 OSM 수집기와 SVG 지도를 확장해 직접 추가했다.
2. 공개 OSM 노선·역 자료를 각 도시별 파일로 분리하고 공식 지도와 역 순서·환승·종착역을 대조했다. 실제 선로 형상 대신 좌표에 놓인 역을 잇는 연결도임을 안내한다.
3. 지도 확대·이동·노선 필터, 이름/역 번호 검색, 한국어 표지판 병기, 역 카드를 재사용했다. 부산·대구에는 수도권 경로 입력이나 ODsay 호출을 연결하지 않는다.
4. 데이터 연결성, 언어, 지역 전환, 키보드, 모바일, 기존 수도권 경로를 검사했다. 원격을 다시 확인하고 검증한 변경을 게시한다.

## 지도 범위와 보완한 오류

| 지역 | 이번에 담은 범위 | 역 수 |
|---|---|---|
| 부산 | 1·2·3·4호선, 부산김해경전철, 동해선 부전~태화강 | 노선별 40/43/17/14/21/23; 환승을 합친 147개 점 |
| 대구 | 1·2·3호선, 하양 연장 포함 | 노선별 35/29/30; 환승을 합친 91개 점 |

대구 대경선·시내버스는 이번 지도에 포함하지 않았다. 전 지역 철도·버스 지원 완료라고 표시하지 않는다. 부산·대구 경로 계산·시간·요금·막차도 이번 구현 범위가 아니다.

- OSM 동해선 관계에서 부산원동이 빠져 있었다. 공식 부산 노선도와 OSM 부산원동 역 노드의 좌표·이름으로 **안락↔부산원동↔재송**을 보완했다. 임의 좌표나 가상 역이 아니다.
- 부전 도시철도역과 동해선역은 별도 점으로 남겨 단순히 가까운 동명역이라는 이유로 자동 환승 표시하지 않는다.
- 동해선 종착역을 자르는 범위를 확장해 개운포·태화강을 보존했다.
- 부산·대구 교대역에 수도권 사전의 ‘서울교육대’ 번역을 적용하던 동명역 문제를 공통 이름/검색 함수에서 막았다. 해당 언어의 확인된 이름이 없으면 데이터의 영어 표기를 사용한다.
- 역 검색 예시는 해당 도시의 서면·반월당과 실제 역 번호를 사용한다. 지도 보기 범위는 해당 도시 역들의 범위에 맞추고, 다른 노선을 필터한 상태라도 선택한 역의 이름을 표시한다.

## 변경 파일

- `data/transit/busan-subway.json`, `data/transit/daegu-subway.json`: OSM 기반 지역별 정적 데이터, 수집일·ODbL 출처 포함.
- `scripts/transit/fetch-subway.ts`: 지역 선택과 수집 JSON 재사용, 모노레일 포함, 부산 자료 보완. 기본 서울 실행과 서울 저장 데이터는 보존.
- `app/components/TransitGuide.tsx`: 기존 지도·검색·카드의 데이터 범위를 지역별로 지정. 외부 링크도 유지. 지역 전환 시 이전 선택·노선 필터 제거. 서울 배경 지도를 부산·대구에 표시하지 않음.
- `lib/transit/subway.ts`: 검색 데이터 범위 인자, 수도권 동명역 번역의 적용 범위.
- `lib/i18n/messages.ts`: 9개 언어의 제공 범위 안내. 과거 ‘지역 지도 미제공’과 ‘다른 지역 미지원’ 문구 갱신.
- `lib/transit/regional.test.ts`, `app/components/TransitGuide.test.tsx`: 연결성·역 수·누락 보완·동명역·지역 UI 회귀 검사.

새 의존성·DB 스키마·키·Render 인증 설정은 바꾸지 않았다. 예약·외부 발송·결제·AI 핵심 상태 머신도 바꾸지 않았다.

## 실행한 검증

- `npm test`: 46개 파일, 320건 통과. 지역 검사는 정적 데이터와 UI 검사이며 실제 API 성공 횟수가 아니다.
- `npm run validate:types`: 기존 요청 유형 5개 통과.
- `npm run build`, `npx tsc --noEmit --noUnusedLocals --noUnusedParameters`, `git diff --check`: 통과.
- Chrome 로컬: 부산원동 K116 검색·역 카드·노선 색, 대구 하양 149 키보드 선택, 대구에서 Seoul 검색 결과 없음, 노선 필터와 `+` 키 확대 확인.
- 서울역→명동 기존 연결 경로: 4호선 2개 역·환승 없음 표시 확인. 로컬 실요금 검사는 아니다.
- 수도권 경로가 표시된 뒤 대구 선택: 이전 경로/수도권 입력/이전 역 카드가 모두 제거됨.
- 390×844: 부산·대구 모두 가로 넘침 없음(`scrollWidth=390`). 9개 화면 언어에서 부산 선택·자체 SVG·자리표시자 해소·390px 유지 확인. 원어민 감수·음성 청취·실기기 검사는 아니다.
- 새로고침: 서버의 기본 서울 화면 뒤 브라우저 준비가 끝나면 저장한 부산 표시 지역 복원. 언어 변경 시 지도 선택이 여행 보드를 바꾸지 않음.
