## 논리적 작업 순서

1. 증상 재현: SVG 이벤트, 노선 수집 좌표 범위, 경로 계산, API 호출, 기존 이동 안내 흐름을 추적했다.
2. 공통 원인 수정: 이름표 선택, 외곽 데이터, 누락 역을 건너뛴 가짜 연결 방지, 같은 역 수에서의 불필요한 환승 방지를 고쳤다.
3. 기존 기능 재사용: 별도 교통·시간 API나 의존성 없이 기존 도시 이동 후보와 브라우저 Intl 시간대 규칙을 사용했다.
4. 표시의 사실성 점검: 정적 연결·실시간 조회·예매 사이트·사용자 기록을 구분했다.
5. 단위 검사, 타입 검사, 빌드, 실제 Chrome 데스크톱·390px 화면과 다국어 표시를 검토했다.
6. 운영 반영 결과는 아래 배포 기록으로 별도 확인한다.

## 추가로 발견해 고친 사항

- 역·노선 선택만 해도 발생하던 ODsay 자동 호출을 제거했다. ‘시간·요금 조회’를 누를 때만 호출한다. 한 조회에 막차 확인 등 여러 요청이 들 수 있음을 안내한다.
- 기존 캐시를 재사용한다. Basic 요금제에서 언어만 바꾼 재조회는 같은 데이터를 재사용하는 모의 요청 수 검사로 확인했다. 캐시를 새로 만들거나 호출 한도를 우회하지 않았다.
- 조회 중 출발·도착·언어·출발시각·휴일 조건이 바뀌면 오래된 응답을 현재 경로 결과에 적용하지 않는다.
- 목적지 전에 종착하는 열차를 방면 후보에서 제외했다. 정적 운행 계통 자료가 없으면 방면을 추측하지 않는다.
- 배경 선로 자료 밖의 외곽 연결은 역 연결선으로 표시하며 선택·경로 이동 범위를 확장했다.
- 이동 후보를 저장하는 절차에서 실제 검색처럼 보이던 단계별 대기 연출을 제거했다. 준비 기록 저장 실패는 성공으로 표시하지 않는다.
- 김포공항→서울역처럼 다른 터미널을 임의로 30분 환승으로 이어 총시간을 계산하지 않는다. 빠진 이동 구간과 확인 필요성을 해당 후보에 표시한다.
- 정적 데이터의 첫 후보를 자동으로 ‘추천’이라고 표시하지 않는다. 항공 탑승 시간은 공항 접근·대기·수속·보안검색을 포함한 전체 시간이 아니다.
- 역방향 항공 검색 링크도 실제 출발·도착 방향으로 수정했다.
- 지역 간 후보의 한국어 역·공항 이름에 영문을 병기했다. 경주 KTX역의 옛 명칭 ‘신경주역’을 현재 ‘경주역’으로 수정했다.
- 시외버스 예매 링크는 영문 T-money 사이트로 연결했다. 부천시청역의 누락된 영문 이름을 공식 안내에 따라 보완했다.
- 사용자가 예약했다고 표시한 기록은 실제 발권·공급자 확인으로 오해하지 않게 안내한다.

## 구현 범위와 남은 확인

- 정적 노선도는 목록에 있는 18개 노선의 연결도다. 수도권의 모든 노선·신규 연장을 완전히 포함했다고 주장하지 않는다. 이번에 정자·수원·오이도 연결은 복구했다.
- 실제 최단시간·급행·대기·막차·요금은 외부 교통 데이터가 필요하다. ODsay는 앞선 운영 점검에서 일일 30/30 한도 및 429가 확인되어 이번에는 추가 실호출하지 않았다. 인증·실제 요금 조회 성공은 아직 미확인이다. 한도 초기화 후 1개 대표 경로로 확인해야 한다.
- 노선도는 지리적 연결도를 정돈한 것이다. 전국 노선의 공식 도식 노선도 전체를 새로 디자인한 것은 아니다. 실제 외국인 사용자의 미적 선호·선택 성공률은 아직 측정하지 않았다.
- 시간대는 국가 추정 대신 거주 도시를 선택한다. 기기 시간대가 거주지와 다를 수 있어 확인 안내를 표시한다. 도시 목록은 브라우저가 제공하는 IANA 목록이며 선택값만 해당 브라우저 세션에 보존한다.
- 교통편은 팀이 정리한 계획용 후보다. 실시간 좌석·현재 요금·판매 여부·공항 간 연결 가능성을 검증한 데이터가 아니다. 날짜를 골라도 공식 사이트의 검색 조건이 자동 입력되거나 예약되는 것은 아니다.
- 9개 언어의 추가 화면 표시·넘침을 확인했으며 원어민 검수·실기기 터치·음성 품질 검사는 별도다.

## 과제와의 정합성

C-02의 핵심은 목표→도구 선택→실행→결과 관찰→다음 행동의 에이전트 흐름과 적용 전/후 Workflow 비교다. 이번 이동·시차 기능은 여행 준비를 보조한다. 호텔 문의의 승인 게이트·모의 발송·조건부 회신·이행 확인 절차는 그대로 유지한다. 지도 기능 수나 테스트 개수를 사용자 성과·절감률로 발표하지 않는다.

팀 등록안의 외국인 4~5명 사용 관찰은 팀 계획이며 아직 이 보고서의 실측 결과가 아니다. `docs/EVAL-workflow.md`의 같은 가상 과업·순서 통제·능동시간/AI 대기 분리 기준으로 핵심 문의 흐름을 우선 관찰하고, 별도 짧은 이동 과업에서 역 이름 선택·시차 이해·미확인 환승 인지를 기록하면 된다. 서로 다른 과업의 시간을 한 절감률로 합치지 않는다.
