## 4. 실제 ODsay 대조 내용

입력은 인천공항1터미널→명동, 평일 시간표, 출발 기준 21:00 또는 23:59이다. 어댑터 검사는 `2026-10-07`, 화면은 가상 보드의 `2026-10-20`을 사용했다. 두 날짜 모두 평일 구분으로 보낸다. API는 날짜 전체를 받지 않으므로 특정 미래 날짜의 운행을 확정하지 않는다.

| 조회 | 수신·확인한 결과 | 의미 |
|---|---|---|
| 21:00 시간표 경로 | 21:03 출발 → 22:02 도착, 59분, 환승 1회, API 요금 4,750원 | 실제 수신값. 요금의 독립 검증이나 급행/직통의 최종 결제 금액 보장은 아님 |
| 환승 구간 | 21:46:30 → 21:54:30, 8분. 역명·노선명 필드 없음 | 수정 후 환승 시간으로 표시, `undefined`나 임의 역명 없음 |
| 23:59 시간표 경로 | 첫차 대체 안내 코드 2, 대체 출발 05:24 | 정상 경로 카드는 0개, 첫차 대체 안내만 표시 |
| 일반 경로+역 시간표 | 인천공항1터미널·서울역 시간표 수신, 고정 21:00 기준 구간별 대기·탑승 계산 실행 | 일반 열차 기준 계산. 실제 탑승·환승 성공 보장은 아님 |

시각 지정 결과에는 급행/직통이 포함돼 승차권 조건과 최종 요금 확인 안내를 추가했다. 일반 경로의 기존 막차 계산은 급행 정차 근거가 부족한 열차를 제외하므로 두 조회의 소요시간이 같을 필요는 없다.

공식 규격: [ODsay API Reference](https://lab.odsay.com/guide/releaseReference?platform=web). 공항 안 걷는 시간·호텔까지 이동은 이번 시간표 조회에서 제외하며 호텔 도착 예정은 자동 저장하지 않는다. 00~04시 출발의 운행일 규칙은 여전히 미확인이다.

| 버스 | 팀 결정으로 제외 | 기존 정류장 순서·방향 요구의 재포함 여부는 팀 결정 |
| 배포 사이트 | 기존 배포 상태 유지 | 이번 변경 배포·배포 ODsay 검증은 하지 않음 |

**외부 조건이 필요한 남은 일:** Booking 제휴 자격, 원어민·음성·실기기 검토, 실제 사용자 관찰, 교재 원문 기준 확인. 조건 이행·기한과 외부 예약 결과는 이용자 확인이며 앱의 독립 검증이 아니다. ODsay IP가 다시 바뀌면 기존 앱의 등록 IP를 갱신해야 하며, 호출 한도에 도달하면 조회가 중단될 수 있다.

## 6. 전후 Workflow와 측정

| 단계 | AI 적용 전 | 마중 적용 후 |
|---|---|---|
| 자료 준비 | 예약 정보·연락처를 직접 찾음 | 예약 정보를 보드에 넣고 확인 |
| 조건 정리 | 날짜·도착 시각·연락 방법을 직접 정리 | 보드와 기존 대화를 활용하고 빠진 것만 확인 |
| 요청 작성 | 번역·역번역을 반복 | 한국어 초안과 역번역을 확인·수정 |
| 발송 | 별도 메일 도구에서 모의 발송 | 최신 원문·수신처·사실 승인 후 모의 발송 |
| 회신 해석 | 직접 번역하고 조건·기한을 판단 | 회신 분류·조건 안내, 불확실하면 이용자 확인 |
| 후속 처리 | 할 일·기한을 따로 관리 | 조건부 유지/답장, 실제 이행·기한 확인 후 문의 해결 |

실제 참여자 관찰은 **0건**이다. 예상치 58분·7분을 실측으로 쓰거나 절감률을 산출하지 않는다. 앱의 “회신 대기 제외 경과 시간”과 관찰자가 재는 “능동 조작 시간”은 다르다. 문의 해결·조건부·거절 건수를 구분하고, 새 예약 확정이나 실제 투숙 완료로 세지 않는다.

빈 관찰 기록 양식은 [EVAL-workflow.md](EVAL-workflow.md)에 있다. 같은 가상 예약·같은 회신·같은 과업 종료 기준을 적용하고 자료 준비 시간을 포함한다. C 유형 과제 및 10/13 제출·온라인 코칭, 10/15 발표는 전달받은 기준이며 교재 원문을 독립 확인하지 않았다.
