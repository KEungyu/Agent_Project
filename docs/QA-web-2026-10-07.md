## 2. 확인된 원인과 수정

### ODsay 호출 경계

기존 Render 환경의 키는 ODsay 앱의 **Server 키**와 일치했다. 그러나 Render 발신은 공유 범위 `74.220.52.0/24`, `74.220.60.0/24`이고 ODsay에는 각 범위의 시작 주소만 단일 IP로 등록돼 있었다. 이 설정은 범위 전체를 허용하지 않는다. ODsay의 동일 Render 사례 답변도 IP 대역 인증을 지원하지 않으며 WEB 프론트엔드 호출을 대안으로 안내한다. 특정 실패 요청의 실제 발신 IP는 이번에 측정하지 않았다. 키 불일치를 확정 원인으로 쓰지 않는다.

무료 WEB 방식으로 연결할 코드를 구현했다. `NEXT_PUBLIC_ODSAY_WEB_KEY`가 있으면 일반 경로·역 검색·시각 지정·막차 시간표 모두 브라우저에서 ODsay로 직접 요청한다. 없으면 기존 서버 방식을 유지한다. WEB 실패 시 서버로 자동 우회 재시도하지 않는다. Origin/Referer를 위조하거나 인증 우회 프록시를 만들지 않았다.

- `lib/transit/routes.ts`: 기존 서버 액션의 역 검증·경로 조회·첫 추천 경로 막차 검사를 공유 함수로 옮김. 전달된 WEB 옵션을 모든 하위 조회에 그대로 전달.
- `app/actions.ts`: 기존 서버 액션을 공유 함수에 연결. 서버 키는 서버에 유지.
- `app/components/TransitGuide.tsx`: WEB 키를 명시적으로 전달하는 브라우저 경계 추가. 기존 날짜·공휴일 변경 시 결과 제거와 확인 게이트 유지.
- `lib/transit/odsay.ts`: 같은 진행 중 조회 공유, 키별 성공 캐시 분리. 잘못된 키 인코딩·null 응답·파서 예외는 비밀 없는 오류로 반환. 실패 캐시 없음.
- 일반 경로의 요금 누락·null·비수치·음수는 0원이나 운행 없음으로 바꾸지 않고 오류 처리. 기존 검사 자료 중 생략돼 있던 요금을 정상 자료에 보완.

### 공식 예약 사이트와 택시

- `lib/external/open.ts`: 팝업 열기가 예외를 던져도 채팅을 중단하지 않고 실패 상태를 반환한다. 기존 수동 공식 링크·조건 요약·중복 자동 열기 방지는 유지한다. 두 사이트가 실제로 열렸다는 것과 예약 확정은 계속 구분한다.
- `lib/taxi/fare.ts`, `lookup.ts`, `TaxiCalculator.tsx`, `app/actions.ts`: 기존 공항 버튼 좌표를 공유하고, 인천공항 버튼↔서울 이동에는 공동사업구역 시계외 할증 예외를 적용한다. 이미 심야 할증된 요금에 1.2를 다시 곱하던 처리를 가산 비율로 변경했다. 40%와 20%를 곱해 68%로 만들지 않는다.
- 서울시 공식 표의 주간 4,800원, 심야 5,800/6,700원, 20/40% 구간과 기존 경계 검사 결과를 대조했다. 요금은 여전히 도로·정체 가정을 쓰는 **예상 범위**이며 미터기 정확도 검증은 아니다.
- 한계: 서울 경계는 기존 사각형 근사다. 공동사업구역 예외는 확인 가능한 인천공항 버튼 좌표에만 적용하며, 자유 입력 장소 전체의 행정구역 판정은 구현하지 않았다. 다른 택시 사업구역·차종의 확정 요금으로 사용하면 안 된다.

## 5. 남은 운영 조치

1. ODsay URI 입력에 `https://`를 넣어 첫 저장이 거절됐다. `majungi.onrender.com`으로 고쳐 둔 상태이며 **수정 후 확인 클릭·저장 완료는 미확인**이다. 이 입력 오류는 검토자가 바로잡았다. 새 계정에 앱을 만들거나 기존 서버 키를 교체하지 않았다.
2. 소유자가 기존 앱의 URI 저장을 완료하고 개요에서 WEB/URI 키를 확인한다. 신규 인증키 입력·저장 단계는 사용자에게 인계한다.
3. 소유자가 Render에 `NEXT_PUBLIC_ODSAY_WEB_KEY`를 설정한다. 현재 관리 화면에는 아직 이 변수가 없다. Basic에서는 `NEXT_PUBLIC_ODSAY_MULTILANG`을 켜지 않는다.
4. 사용자가 Render 직접 반영을 지시했다. 검증한 수정 브랜치를 커밋·푸시하고 검토·병합한다. 실제 WEB 키가 설정된 환경에서 새 빌드·배포하고 배포 SHA를 확인한다. 공유 IP 시작 주소만 추가하는 방식으로 돌아가지 않는다.
5. 공식 배포 도메인에서 예산을 확인한 뒤 일반 경로·추천 경로 시간표, 지정 시각 역 검색·경로 조회를 소량 실행한다. 인증·429에서는 중단한다. 도메인 저장·배포 성공만으로 인증 해결이라고 기록하지 않는다.

이 세션에서는 배포 사이트에 대한 브라우저 사용이 차단돼 운영 화면을 자동 검사할 수 없다. 다른 브라우저·직접 HTTP·엔드포인트 호출로 해당 제한을 우회하지 않았다. 배포 후 운영 화면·CORS는 사용자가 확인하거나 허용된 환경에서 검증해야 한다.

Booking.com은 현재 공식 홈 링크·조건 복사·사용자 결과 기록만 지원한다. Managed Affiliate 자격이 없다고 확정한 것이 아니라 **자격·토큰이 확인되지 않은 상태**다. 어댑터가 있어도 목적지 검색은 에이전트에 연결돼 있지 않다. 자격·허용 기능이 확보되기 전 API 검색·가격·예약 확정을 완료로 쓰지 않는다. Catchtable Global도 공식 링크 범위를 유지한다. 버스와 직접 예약·결제는 기존 팀 범위대로 제외돼 있으며 원래 아이디어 전체가 구현됐다고 쓰지 않는다.

## 6. 과제와 관찰 준비

팀 보유 `서울대학교 KDT 13기_제2강_20260914.pdf` 82쪽을 렌더링해 확인했다. C는 업무용 AI Agent 앱과 AI 적용 전후 Workflow 정의·비교이고, VectorDB·Git merge는 G의 추가 항목이다. 83쪽의 10/13 제출·온라인 코칭, 10/15 발표 일정도 텍스트로 대조했다. 이번 확인은 별도 최신 변경 공지까지 확인했다는 뜻은 아니다.

`docs/EVAL-workflow.md`를 보완했다. 수동 번역 도구를 쓰는 기존 절차를 “AI 전혀 없음”으로 표현하지 않고, 사용 도구·준비 시간·모의 발송 확인·같은 회신 제공 시점을 고정한다. 능동 시간과 번역/AI 대기, 관찰자 도움, 조건·기한 이해, 모의/미확정 상태 구분을 기록한다. 시연은 영어 요청→보드 확인→초안/역번역→수정/최신 승인→모의 실행→조건부 회신→다음 행동으로 유지한다. 실사용 관찰·만족도·절감률은 생성하지 않았다.
